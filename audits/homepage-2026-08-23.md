# Homepage Audit — `glebkalinin.ru` (2026-08-23)

**Scope.** Homepage only (`themes/gk-nerd/layout/index.ejs`, `home.css`, `variables.css` scoped tokens, header in `layout.ejs`, `main.js`).
**Out of scope.** `/bio/`, `/blog/`, `/archive/`, `/impressum/`, project pages — not in the request, not audited.
**Modes.** Dark (default) + Light via `.page-home.light` token swap.
**Coverage.** Inline static analysis; Chromium-based visual via HTTP fetch of computed HTML/CSS; **light theme driven review not run** (no automated browser tool attached in this session).

## Anti-Patterns Verdict — **PASS (with caveats)**

The redesign's home is intentional, not the AI-template look. It leans on three deliberate choices the brief earned:

- **Monaspace Xenon/Neon VF** (display) + **Geist Sans** (body) — a deliberate split-faces pairing where the body face swap from monospace was the key fix for light-mode legibility.
- **`#F5B8A5` salmon / `#C8745A` terracotta** as `--lead` — accent, not the default AI vermilion/cream combination.
- **One cohesive card family** (`.fx-card`, `.community-card`, `.ch-card`) with consistent 1px soft-border + 16px radius + spring-lift hover grammar. No nested cards, no glassmorphism, no gradient text.

**AI-slop tells found and dismissed:**

| Tell | Present? | Why dismissed |
|---|---|---|
| Cream `#F4F1EA` background | No | `--bg-base` is `#F4F6F8` (light) / `#0C1116` (dark) — cool, not warm cream. |
| Acid-green / vermilion accent on near-black | No | Accent is salmon/terracotta; not the usual `acid-green on black`. |
| Broadsheet hairline rules + dense columns | No | Page is generous on space; `clamp()`-driven fluid type. |
| Hero metrics row (3 numbers + labels) | No | No metric strip — opening is a thesis paragraph. |
| Card grid as default container | Yes (six cards in two grids), but | cards are content-bearing, not filler; each has `kind`/`name`/description/meta — earning the grid. |
| Generic Google-font body face | No | Geist Sans is restrained, used only for prose. |
| Bounce easing | Yes (`--ease-spring`) | Scoped to card lifts (5px), not page-wide. Acceptable; not the bouncy AI tell. |
| Gradient text | No | `--lead` is a flat color. |
| Glassmorphism | Only in `.header-controls` (`backdrop-filter: blur(12px)`) | Small, fixed pill — classic nav-bar pattern, not a hero glass surface. |

**Borderline (worth flagging):**

- The **`.humane-install` "npx" / "/plugin" labels** are a numbered marker pattern (`01 · setup` / `02 · frame` / …). Per the skill: "numbered markers … only appropriate if the content actually is a sequence." The 17 skills are a set, not a sequence. The numbers here are aesthetic — recommend switching to something content-meaningful (category, like "install / frame / prototype / verify / ship") or dropping them entirely. **LOW.**
- **`.home-footer .socials` has 4 of 5 links rendered identically** (`Telegram ↗` `WhatsApp ↗` `GitHub ↗` `LinkedIn ↗` `Tool Building Ape ↗`). When every link is "label + arrow + same color + same weight," the visual hierarchy tells you nothing. **LOW.**

## Executive Summary

- **Issues found: 18** (Critical 0, High 4, Medium 9, Low 5)
- **Most critical (must fix before any deploy that touches light mode):**
  1. `--lead #C8745A` fails AA contrast against the light bg (3.27:1) — affects every link, install-label, CTA hover, kind/meta labels in `.fx-card`.
  2. `--accent #ff6b35` fails AA contrast in light mode (2.84:1) — global `:focus-visible` outline is invisible on light mode.
  3. Zero `:focus-visible` rules in `home.css` — keyboard navigation falls back to the global `#ff6b35` outline (fails AA on light, barely visible on dark).
  4. Theme toggle at 32×32 fails WCAG 2.5.5 target size (≥ 44×44) — also WhatsApp pill at 36×36.

- **Overall:** Dark theme: B+. Light theme: C+ (passes body copy, fails accent everywhere). When the user says "make sure light version is readable," **the light theme is partially broken at the accent level.**

## Detailed Findings by Severity

### HIGH-1 · `--lead #C8745A` fails AA on light bg (3.27:1)
- **Location:** `themes/gk-nerd/source/css/variables.css:118`
- **Severity:** High
- **Category:** Theming / Accessibility
- **WCAG:** 1.4.3 Contrast (Min) — fails AA for body text (4.5:1) and AA Large (3.0:1, marginal at 3.27)
- **Where it lands:** All `.kind` labels, install-command labels, hero CTAs (`.cta-primary` is the lead color), all `a` colors (line 70 of `home.css`), `c-name`, lab-link, `.quote` border-left.
- **Impact:** 11px `.kind` ("01 · setup") is the kind tag above each card title. A user with mild low-vision cannot read it. The CTA "Read the story ↓" (`.cta-primary`) uses `color: var(--bg-base)` over lead — that *is* fine at 11.09:1 — but the **text inside `.cta-ghost`** ("Join a lab", "Read the full skill pack ↗") inherits `--fg` over `--bg-base`, which is fine; the **border** is `--border-soft`, fine. So CTA buttons are mostly OK; the failure is the link-color and label-color usage.
- **Fix:** Darken the light-theme `--lead` to something around `#9F4F38` (~5.5:1) or `#A85840` (~4.7:1). Keep the salmon character; just push the value.
- **Suggested command:** `/normalize`

### HIGH-2 · `--accent #ff6b35` fails AA on light bg (2.84:1)
- **Location:** `themes/gk-nerd/source/css/variables.css:13` (no light override)
- **Severity:** High
- **Category:** Theming / Accessibility
- **WCAG:** 1.4.11 Non-text Contrast (3:1) — fails for UI components and focus indicators
- **Where it lands:** Global `:focus-visible` outline (`variables.css:159`), `.cta-btn`, all default `a` link color (`variables.css:165`), `--accent-glow` shadows.
- **Impact:** A keyboard user tabbing the homepage in light mode gets a focus ring so close to the link color it's nearly invisible. The orange-on-white violates the "non-text contrast" WCAG bar of 3:1.
- **Fix:** Add `.light` override `--accent: #C04A1F` or similar (~4.5:1 against white). Or scope the global `:focus-visible` to use `--lead` instead, which already has a darker light-theme value.
- **Suggested command:** `/normalize`

### HIGH-3 · Zero `:focus-visible` styles in `home.css` — keyboard nav invisible
- **Location:** `themes/gk-nerd/source/css/home.css` (entire file)
- **Severity:** High
- **Category:** Accessibility
- **WCAG:** 2.4.7 Focus Visible (A) — must have a visible focus indicator
- **Impact:** All interactive elements on the homepage — `.cta-primary`, `.cta-ghost`, `.fx-card` (linked hover target is the card title), `.community-card` (whole card is a link), `.install-cmd` (code chips) — fall through to `variables.css:159` which uses the failing accent. Keyboard users cannot tell where they are.
- **Fix:** Add `.page-home :focus-visible { outline: 2px solid var(--lead); outline-offset: 3px; }` plus a transparent outline default for `:focus` to avoid the click-focus flash on `.fx-card` titles that aren't links.
- **Suggested command:** `/harden`

### HIGH-4 · Touch targets below 44×44 (theme toggle, WhatsApp pill)
- **Location:** `themes/gk-nerd/source/css/main.css:76` (`.theme-toggle { width: 32px; height: 32px; }`) and `themes/gk-nerd/source/css/main.css:141` (`.whatsapp-btn { width: 36px; height: 36px; }`)
- **Severity:** High
- **Category:** Accessibility / Responsive
- **WCAG:** 2.5.5 Target Size (AAA, ≥ 44×44) and 2.5.8 (AA, ≥ 24×24)
- **Impact:** Theme toggle fails AAA; WhatsApp pill passes AA (24) but is still below the 44pt comfortable-tap threshold. On touch devices, mis-taps are common; users with motor impairments cannot reliably hit these.
- **Fix:** Bump theme toggle to 40×40 (passes AA), or 44×44 (passes AAA). WhatsApp can stay 36×36 if its hit-area is extended via `padding` rather than width — current code uses `width: 36px; height: 36px` with no padding extension.
- **Suggested command:** `/harden`

### MEDIUM-1 · Skip-to-content link absent
- **Location:** `themes/gk-nerd/layout/layout.ejs` (entire `<body>` opener)
- **Severity:** Medium
- **Category:** Accessibility
- **WCAG:** 2.4.1 Bypass Blocks (A)
- **Impact:** Keyboard users must tab through the entire header, nav links, and Telegram/WhatsApp buttons on every page-load before reaching `<main>`. Six-to-eight wasted tabs on the homepage.
- **Fix:** Add `<a href="#story" class="skip-link">Skip to main content</a>` as the first child of `<body>`. Hide visually until focused.
- **Suggested command:** `/harden`

### MEDIUM-2 · `<html class="dark">` set server-side, overridden by JS on every load (FOUC risk)
- **Location:** `themes/gk-nerd/layout/layout.ejs:2` + `themes/gk-nerd/source/js/main.js:26-27`
- **Severity:** Medium
- **Category:** Performance / UX
- **Impact:** Server renders `class="dark"`, but `main.js` runs `html.className = savedTheme || (systemPrefersDark ? 'dark' : 'light')`. On a light-preference user with no saved theme, the page paints dark then flashes light within ~50ms. The `<style>` block for the bg/color swap lives in `home.css:42-50`, so the flash is just a bg-color flicker, but it is perceptible.
- **Fix:** Inject a tiny `<script>` in `<head>` *before* the stylesheets that reads localStorage and sets `document.documentElement.className` synchronously. Or render the correct class server-side via Hexo's localStorage-unaware template (acceptable tradeoff).
- **Suggested command:** `/optimize`

### MEDIUM-3 · `--font-text` (Monaspace Neon) hard-coded on `body` inside `.page-home` — already fixed but fragile
- **Location:** `themes/gk-nerd/source/css/home.css:46`
- **Severity:** Medium (regression risk)
- **Category:** Theming
- **Impact:** `font-family: var(--font-text)` on `body` would normally cascade Monaspace to all text. The fix at lines 57-68 explicitly overrides prose selectors to `var(--font-sans)`. **However:** if anyone adds a new prose block (`.testimonial p`, `.humane-install > p` already covered, `.humane-section .humane-install p` etc.) without adding it to that selector list, they will silently ship unreadable light-mode body copy again. The `.humane-install > p` was added explicitly (line 50 of home.css for install block) but the selector list lives only at lines 57-68.
- **Fix:** Make the prose-override the default — set `body` to `--font-sans` at the home scope and use `--font-text` (Monaspace) only on display elements (h1, h2, h3, `.wordmark`, links). This inverts the override and makes future prose additions safe by default.
- **Suggested command:** `/normalize`

### MEDIUM-4 · No `aria-current` on nav links during scroll-spy
- **Location:** `themes/gk-nerd/layout/index.ejs:13-17`
- **Severity:** Medium
- **Category:** Accessibility
- **WCAG:** 4.1.2 Name, Role, Value (A) — recommended (not required) for nav state
- **Impact:** The nav has `the story / the method / labs / community` but no scroll-spy is implemented, so the active section is never indicated to AT users. Acceptable to skip scroll-spy entirely; flagging only because the affordance exists in the markup.
- **Fix:** Either implement scroll-spy with `IntersectionObserver` setting `aria-current="page"` on the matching nav link, or accept the absence. If kept absent, document the decision.
- **Suggested command:** `/harden`

### MEDIUM-5 · `home.css:34-36` -- Monaspace Neon 300/400 webfonts loaded but unused
- **Location:** `themes/gk-nerd/source/css/home.css:22-36`
- **Severity:** Medium
- **Category:** Performance
- **Impact:** Two webfont requests (`latin-300-normal.woff2`, `latin-400-normal.woff2`) are loaded as fallbacks for the variable instances declared at lines 10-19. The variable instances (`font-weight: 200 800`) cover 300 and 400 already, so the static webfonts are dead weight — ~40KB extra on every cold load. Variable fonts handle all weights via interpolation.
- **Fix:** Delete the two static `@font-face` blocks at lines 22-36. Keep the variable instances.
- **Suggested command:** `/optimize`

### MEDIUM-6 · `motion.js` and `vault-graph.js` always loaded on homepage — `motion.js` is 200 lines of GSAP orchestration that may fail
- **Location:** `themes/gk-nerd/layout/layout.ejs:62-67`
- **Severity:** Medium
- **Category:** Performance
- **Impact:** GSAP is loaded from CDN (`cdn.jsdelivr.net`) with an 8s timeout fallback. If the CDN is slow (which the recent CI hiccups suggest it can be), `motion.js` will block paint or paint in a stuck-mid-state. The fallback (`.gsap-failed` class) handles this, but the cost of always loading it on every homepage visit (and on first paint) is real.
- **Fix:** Defer `motion.js` even more aggressively (`async` instead of `defer`), or load it on idle (`requestIdleCallback`). Verify the fallback still fires.
- **Suggested command:** `/optimize`

### MEDIUM-7 · Footer copyright `<span>` with no `id` — screen-reader dependent
- **Location:** `themes/gk-nerd/layout/index.ejs:193`
- **Severity:** Medium
- **Category:** Accessibility
- **Impact:** `<span>© 2026 Gleb Kalinin · Berlin, Germany</span>` is read by screen readers as a single phrase. The middle dot is read literally; "Gleb Kalinin" without a comma can be ambiguous. Minor but cumulative.
- **Fix:** Wrap in a `<small>` element with `aria-label="Copyright 2026 Gleb Kalinin, Berlin, Germany"`. Or use `<address>` for the city.
- **Suggested command:** `/harden`

### MEDIUM-8 · Image lazy-loading works, but first chapter image isn't `priority`/`fetchpriority=high`
- **Location:** `themes/gk-nerd/layout/index.ejs:60-64`
- **Severity:** Medium
- **Category:** Performance
- **Impact:** Every `<picture>` uses `loading="lazy" decoding="async"`. This is correct for chapters 2-6 (below the fold), but the **first** chapter card image is *above* the fold on most viewports. Lazy-loading it delays LCP by 100-300ms on slow connections.
- **Fix:** For `i === 0` only, swap `loading="lazy"` → `loading="eager"` and add `fetchpriority="high"`.
- **Suggested command:** `/optimize`

### MEDIUM-9 · `--font-text: "Monaspace Neon"` ships in fallback chain before Geist
- **Location:** `themes/gk-nerd/source/css/variables.css:114`
- **Severity:** Medium
- **Category:** Performance / UX
- **Impact:** When Monaspace fails to load, the fallback is `"Geist Mono", "SF Mono", Consolas, monospace` — that's correct, all monospace. But on systems with neither Monaspace nor Geist Mono installed, the user gets their browser default (`Menlo` on macOS, `Consolas` on Windows, `monospace` on Linux). The display size (`clamp(46px, 7.2vw, 100px)`) plus browser-default monospace at 100px will look like a different page. The hero deserves `system-ui` fallback before `monospace`.
- **Fix:** Reorder to `'Monaspace Xenon', 'Geist Mono', ui-monospace, 'SF Mono', Menlo, monospace` (note the `ui-monospace`).
- **Suggested command:** `/normalize`

## Patterns & Systemic Issues

1. **Token system leaks across themes.** `--accent` (`#ff6b35`) has no light override, but `--lead` does. The reason light mode fails on `--lead #C8745A` is the same shape of issue that would bite `--accent` if it had been used for buttons. The pattern: **any color token used for "accent on text" must have a light override.**
2. **`home.css` overrides `body` prose by enumeration.** A defensive fix would be to set the safe default on `body` and use the monospace face only on display elements.
3. **Focus indicators live at the bottom of the cascade.** Global `:focus-visible` in `variables.css` is the only line of defense for keyboard focus. Anything that scopes deeper (`home.css`, `bio.css`) loses it. A `.page-home :focus-visible` block would patch this.

## Positive Findings (preserve)

1. **Heading weight-bloom via `@supports (animation-timeline: view())`** at `home.css:82-92` is a clean CSS-only scroll-driven animation with a `.gsap-failed` fallback. This is exactly the kind of progressive enhancement the design called for.
2. **`.page-home` scope on home.css.** Every selector under `.page-home` prevents design-token leaks to bio/blog pages. This is the right architecture for a multi-page site with separate aesthetics.
3. **`<picture>` element with AVIF + WebP + fallback** (`index.ejs:60-64`) for chapter images is the modern standard. The conversion pipeline exists; the markup is correct.
4. **`prefers-reduced-motion`** is respected at three levels: `home.css:573-586`, `main.js:75` (early return on IO reveal), and `motion.js` (per the file header). This is a mature accessibility implementation.
5. **Dark palette is genuinely AAA.** `fg/muted/lead` all exceed 11:1 on `bg-base`. The site is *more* accessible in dark than light — which is not the typical pattern.
6. **Honest data layer.** `source/_data/redesign.yml` drives every section by loops; no copy is in the templates. This makes audits and content edits trivial.
7. **The new Humane section** (lines 163-243 of `index.ejs`) reuses the existing `.fx-card` grammar without introducing new patterns. It inherits all hover/responsive behavior automatically. Good.
